## Resultado

Caja prioriza el efectivo esperado y agrupa tarjeta, ingresos y retiros con cifras legibles. Conserva ventas en efectivo, fondo y último corte. Los movimientos muestran tipo, signo, importe, motivo y fecha. Ingreso, retiro y corte usan diálogos premium con labels asociados, errores junto al campo, teclado decimal, foco visible y estados de carga.

Historial usa tabla completa desde 1200 px y tarjetas con todos los datos en móvil/tablet. El detalle distingue responsable/período, totales, recuento, diferencia, fondo conservado, notas y ventas. Se mantienen los enlaces de detalle y ticket, la paginación y las condiciones de datos nulos. No se modifica lógica comercial ni contenido de otros módulos.

## Entorno y límites

La sesión disponible redirige a login. Se simulan únicamente respuestas de página en el navegador, con los componentes y assets reales de `http://localhost`. Para observar errores/loading se instrumenta temporalmente la respuesta JavaScript de Caja en Playwright, exponiendo las instancias montadas de `useForm` solo en ese navegador; no se modifica el bundle del servidor ni el código del proyecto. Se bloquean solicitudes distintas de GET/HEAD. Esto verifica presentación y atributos, no autenticación, autorización, validación comercial ni persistencia. Los ids de cortes y tickets de las capturas son ficticios.

El MCP predeterminado no encontraba Chrome. Se usa el Playwright MCP ya instalado con el Chromium existente, stdio y socket Unix temporal, sin puerto TCP ni servidor de preview. Al finalizar se retiran interceptores e instrumentación, se cierra el navegador y se detiene ese proceso auxiliar. Scripts, snapshots, logs y capturas de referencia descartables se retiran; se conserva únicamente la evidencia vinculada.

Se actualizan las imágenes locales de app y Nginx para publicar el frontend; MySQL y Redis conservan sus contenedores y volúmenes. Localhost responde HTTP 200. Manifest de checkout/app/Nginx idéntico: `95355843924e770fc3f34e2a414bda1c35e119a54287ea0baf9b46ff7d183a7c`.
